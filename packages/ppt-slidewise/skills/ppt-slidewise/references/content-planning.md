# 内容策划：从材料到可讨论的内容稿

目标：把复杂判断拆成可检查的步骤，减少在错误方向上制作页面的返工。完成表格不代表逻辑正确；不得用主观打分代替问题定位。当前为Skill行为规范，不是CLI机器强制的状态机。

## 1. 第一轮：讨论目的与方向

先读已有材料和对话，判断哪些信息已经明确。第一轮自然地讨论：

- 这份材料给谁看，对方已经知道什么？
- 希望看完后理解什么、讨论什么，或作出什么决定？
- 本次重点讲哪件事，哪些暂时不展开？

首轮避免细问，每次1–2个关键问题，尽量每题三个选项加自定义输入。体量可粗选“5–10分钟短报告 / 10–30分钟常规报告 / 长篇内容”，不要追问精确页数或把时长硬换算页数。优先确定用途和方向，已提供的信息直接记录；字体、配色和动画留后续。[轻量询问](intake.md)给出题库与可点击表单。题库不是一次性全问的清单。

先用两三句话说明材料目前能支持什么、方向哪里不确定，再提问题。不预先替用户决定“争取预算”“推荐某方案”或“证明方案更优”。目的仍不清楚时，不生成逐页正文、不调用create/export、不做视觉稿。

**例（合成材料）**：用户只说“把测试笔记做成PPT，给领导看”。

- 不合适：立即生成10页“方案A优势与推广计划”，然后问用户喜欢什么颜色。
- 合适：说明笔记主要是初步测试结果，尚不清楚此次是同步进展、讨论问题还是请求决策；先询问汇报用途和最想让对方带走的一点。领导身份已足够明确时，不重复追问无关职级。

阶段成果：简短任务理解，包含用途、受众、希望达成的结果、范围、表达重心；未知项标未知。用户回答足以确定方向即可进入材料整理，不必额外增加“请批准第一步”。

## 2. 整理事实、判断、假设和缺口

保留来源与定位：文件/段落/图号或用户提供的说明；网页来源记录链接与日期。为重要证据分配E01等编号，后续逐页引用。不擅自把项目历史、其他聊天或演示数据混入当前任务。

| 类别 | 如何处理 |
|---|---|
| 事实 | 原材料明确记录的结果；保留条件、单位、日期和样本范围 |
| 判断 | 解释或推导，列出支撑证据和推理；不写成直接测得 |
| 假设 | 有待验证的解释或预期，用明确标记保留 |
| 缺口 | 缺什么、影响哪项主张、怎么处理：补材料/限定结论/删除主张/移到待讨论 |

不要求材料齐全才能开始全部工作：只暂停依赖关键缺口的结论，其余内容继续。用户允许检索时按约定补充来源；外部资料不能冒充内部测试结果。信息冲突并列呈现，不能静默取平均或挑有利结果。

**例（合成）**：A记录12ms，B记录9ms，但两次负载不同。可写“现有两次记录为12ms与9ms，条件不同，暂不能直接比较”；不能写“B性能提升25%”。“材料写了一个数字”与“这个数字足以支持推荐”是两回事。

## 3. 选择主线并解释取舍

先写核心问题，再选择适合目的的组织方式。下列是候选，不是固定标题模板：

| 用途 | 常用组织路线 |
|---|---|
| 请求决策 | 问题→评价标准→选项比较→推荐及代价→需作出的决定 |
| 技术研究 | 研究问题→条件与方法→结果→解释→限制→下一步 |
| 进展汇报 | 原目标→实际进展→偏差和原因→风险→后续安排 |
| 知识讲解 | 要理解的问题→基本模型→例子→误区→应用 |

讲清“为何这样排序”。材料与目的发生冲突时，说明现有证据能支持哪种讲法。只有存在实质不同的路径时才给两种选项，不机械产出A/B/C。先确定必须讲、可以合并、放附录的内容，再估计页数；不先凑10页。

主线写入最终内容逻辑审查稿。方向有关键歧义时自然讨论，不再设置第三个固定审批节点；R1统一审查目的、逻辑链与实际内容。已有明确回答直接复用。

## 4. 把主线展开为逐页实际内容

每页写以下字段，例子见模板：

1. 页面标识和本页要回答的问题。
2. 本页核心信息及拟用标题，主张的限定条件不能丢。
3. 实际正文：准备放到页面的文字，不是“介绍优势”“展示数据”等占位说明。
4. 依据：证据编号，或标“暂无依据/讨论问题”。
5. 图表/图片：帮助解释什么，素材是否已有、缺什么；已有图片不能擅自替换成装饰图。
6. 前后关系：承接什么，下一页为什么出现。
7. 讲稿或附录：现场解释但不挤进页面的细节。
8. 待确认项：影响当前页的事实或取舍。

按章节或2–4页一组写，检查后再继续，不要求每组都询问用户。证据不足时写问题页或限制页，不把主题标签硬变成肯定结论。没有内容的页面合并或删除，不能靠装饰、套话和示意图补满。

## 5. 内容审查与返工

带着当前任务目标逐项检查，不凭“整体不错”结束：

- 只读标题能否理解论证路线？是否有突兀跳跃或重复？
- 主要结论能否对应证据？条件、单位、样本范围是否一致？
- 数量、占比、最大/最少等比较须根据同一张表实际计算；公司/作者归属逐项查来源，不能凭相邻编号或记忆归类。研究范围外的对象不等于未归属或不存在。
- 不从几个样本直接推断企业战略迁移、成本优势、量产能力或具体产品波长；这些判断要有额外直接依据。加“研究性推断”标签也不能替代证据。
- 有没有把猜测当事实、相关性当因果、不同比较条件当直接对比？
- 目的要求的内容是否遗漏？是否需要反例、风险或限制？
- 结尾有没有回答开头的问题？需要决策时，请求是否具体？
- 素材缺口是否仍被占位文本掩盖？一页信息是否需要拆分？

审查输出“页面/问题/影响/修改办法”。先修方向和证据，再修文字密度。没有发现问题时说明检查了哪些范围与仍未知的事项，不声称无风险。对事实的疑问回到第2步，对目的与主线的疑问回到第1/3步；不把所有问题都交给视觉专家。

**R1：内容逻辑审查。**用[用户审查稿模板](../assets/content-review-template.md)给出可阅读、可留存的内容逻辑稿：目的与受众、主张与逻辑链、各页实际核心内容、证据支持关系和关键缺口。内容完整呈现在聊天里，或保存为文档并给出可打开链接；只说“已策划好”或仅报文件路径不算交付。先自查再交用户，未认可前不展开整套制作。缺口必须明示，不以空泛标题或占位符伪装为完整内容。

## 6. 制作与后续修改

R1通过后把确认内容映射到CLI支持的版式，先制作1–2页样例，不改变实质含义。**R2：视觉与布局审查。**样例需有实际PPTX、可见预览和代表性内容，供用户判断信息密度、配色、风格、字体和布局。优先选择正常文字页和图文/数据较密页，不能只做漂亮封面。反馈认可后才展开整套；细则见[审查节点](review-gates.md)。渲染只在需要展示布局时进行，避免每次内容讨论都重导出。

- 改位置/字号：更新版面，不重新策划全套内容。
- 改数字/结论：更新内容稿，检查引用该内容的标题、图表、摘要和结尾。
- 改顺序：检查前后过渡，保持稳定页面ID以追踪修改。
- 改汇报目的：明确旧方向已被替换，更新任务理解、主线和受影响页面；未受影响的资料继续复用。
- 用户在SlideWise改了字：read最新保存稿再工作，不用旧YAML重新生成覆盖。

初期不引入多专家流水线。模型自己完成分步策划；必要时让用户判断业务取舍。效率来自在文字阶段早纠偏、减少无效生成，不来自省略关键讨论。
