# 视觉专家参考包

当前五类、17 张经过视觉检查的参考截图，每类至少两张。分类是工作用导航，不宣称是唯一或完整的设计史分类；一个作品可以有多个标签。主题、密度和风格可以自由组合。

涉及仿真平台、工具或产品界面时，优先查看[专题参考](collections/product-ui/README.md)，按任务挑选相关案例；这些是获准参考，不是已经选定的设计方案。

## 最小开工卡

新任务开工必须完成一次简短确认，回答前不制作本任务设计稿。可合并成以下三组问题；已知答案先概括成推荐默认，请用户一次确认或修改：

1. **做什么、给谁看？** 主题/用途、受众、希望完成什么行为，有哪些必须保留的内容？
2. **希望什么感觉？** 喜欢和不喜欢什么，有没有链接或图片参考；亮色、暗色还是双主题？
3. **怎么一起选？** 对风格术语熟悉吗，需要我用 A/B 图片说明两种方向吗；希望看几份风格小样？

允许“说不清/你推荐”。这是对所问问题的回答，不自动豁免其他关键缺项。需要风格帮助时可以展示两张现有参考图片，标明适用点，用“更克制/更鲜明”“更紧凑/更舒展”等日常语言解释。用户未给出创作方向前，可做资料与工具检查，不把假设当作已确认偏好。

简短 brief：`目的 / 受众 / 已确认偏好 / 本次明暗 / 参考及喜欢的具体部分 / A-B 是否需要 / 小样数量 / 不可改内容 / 输出位置`。

面向普通用户，专业细节由专家决定和检查，不要求用户确认字体/色号/间距参数表。“可以开始”和“专家负责细节”不替代开工确认；只有本任务已经确认，或用户明确要求本次完全免询问，才直接出稿；解释推荐原因并吸收拒绝理由，用“保留 / 避免 / 下一版调整”承接反馈。

公司汇报 PPT 走[简化流程](scenarios/company-ppt.md)，已有模板不默认风格二选一。[常用搭配](pairings.md)由专家逐渐积累，区分候选推荐与用户已确认默认。

## 分阶段控制工作量

简短确认 → 同内容的 A/B 风格小样 → 用户选择或反馈 → 深化一个方向 → 完整实施与检查。

小样一般半屏到一屏，只包含代表性标题、正文与一组图表/卡片，静态图或轻量 HTML 均可。只需看得出风格且内容可读；不做整页、子页面、全量数据和完整交互，也不为两个未选方向跑全套适配与回归。选定前停在小样，别以“同完成度”理解为“两套完整成品”。

已确定公司模板或用户明确委托专家选方向时，通常直接走一个方向；不强制 A/B。

## 读取路线

1. [分类与标签](taxonomy.md)：从任务挑选 1–2 类。
2. 打开对应目录的 README 与两张图片：
   - [克制极简](styles/minimal/README.md)
   - [编辑叙事](styles/editorial/README.md)
   - [功能理性](styles/functional/README.md)
   - [鲜明表达](styles/expressive/README.md)
   - [工程手作感：Heron AI](styles/technical-craft/README.md)
   - [编辑叙事中的 Anthropic 专题](styles/editorial/anthropic.md)
3. 用 [few-shot 方法](few-shot.md) 把参考转成当前任务的设计决定。
4. 若现有样例不合适，按[来源与入库标准](sources.md)选新样例，不强套图库。

首批截图是同一时期的公开页面视口，不证明其动效、移动端或可访问性全部合格。参考标注说明可借鉴和需警惕的部分。浏览器右侧粉色浮层不是作品设计，忽略它；品牌、文案和照片不直接用作交付资产。
