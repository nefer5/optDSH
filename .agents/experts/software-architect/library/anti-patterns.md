# 反模式

每条：症状 / 检测信号 / 危害 / 改法 / 何时可以不改。检测信号中的发现 id 来自 `{{KIT_ROOT}}/scripts/arch_scan.py`；grep 线索是正则，用宿主的搜索工具执行。扫描命中只是线索，结论要读代码确认；未读代码的判断标为“推断”。

整改顺序统一：**先止血**（停止新增同类问题）→ **再收敛**（合并重复、移动落点）→ **最后重构**。

## AP-01 上帝文件

- **症状**：一个文件同时做参数解析、业务计算、IO、格式化输出；多数改动都要碰它；多个 Agent 同时改它产生冲突。
- **检测**：`ARCH-SIZE`；文件内顶层定义 >30 个；import 涉及 CLI 库、HTTP 客户端、数据库驱动三类以上。
- **危害**：改动范围不可预测，测试只能端到端，并行协作冲突。
- **改法**：按职责拆成 2–4 个文件（入口 / 核心 / IO / 格式化），先移动不改逻辑，每步跑测试；原文件保留为装配入口。
- **何时可以不改**：生成文件、协议/数据表、测试数据；稳定且近期无改动计划的老代码（只止血：新功能不再往里加）。

## AP-02 平行重复实现

- **症状**：同一能力两处实现（两个配置加载器、两个路径工具、前后端各写一份校验）；修 bug 只修了一处。
- **检测**：grep 相近名称：`(load|read|parse)_?config`、`(get|resolve)_?(root|path)`、`format_?(date|size)`；同一错误信息文本出现在多个文件；同一正则字面量出现两处以上。
- **危害**：行为分叉，后续 Agent 不知道该改哪个，问题被“修好”后复发。
- **改法**：选行为更完整、调用方更多的一份为归属；另一份改为调用它或删除；在 ARCHITECTURE.md“新增 X 放哪里”写明归属。
- **何时可以不改**：跨语言或跨进程边界且共享代码成本更高（前后端各自校验但规则来自同一份 schema 时可接受）；明确的过渡期，写明删除条件。

## AP-03 硬编码路径与魔法值

- **症状**：业务代码出现本机绝对路径、主机端口、模型名、阈值数字；凭据写在源码或样例里。
- **检测**：`ARCH-HARDCODE`、`ARCH-SECRET`；grep：`[A-Za-z]:[\\/]`、`/(home|Users)/`、`https?://(localhost|127\.0\.0\.1)`、`(api[_-]?key|secret|token|password)\s*[:=]`；ruff `PLR2004`、clang-tidy `readability-magic-numbers`。
- **危害**：换机器即坏；密钥泄露；同一阈值多处不一致。
- **改法**：路径改为相对项目根或从配置/参数注入；常量命名后集中到 `config`/`constants` 一处；凭据改环境变量并轮换已泄露的值（只报告位置，输出脱敏）。
- **何时可以不改**：一次性脚本顶部集中声明的路径常量；测试夹具；`[hardcode] allow_paths` 声明的文件；协议规定的固定值。

## AP-04 入口里写核心逻辑

- **症状**：`main()`、CLI 回调、HTTP handler、React 组件里写了计算、规则判断、数据转换；要测逻辑必须启动整个程序。
- **检测**：入口文件超过约 150 行；入口文件中有循环 + 条件嵌套计算；核心函数在其他地方没有调用者；测试 import 入口模块或用子进程测逻辑。
- **危害**：逻辑无法复用到第二个入口，测试慢且脆。
- **改法**：把逻辑提取为接收普通参数、返回数据的函数，入口只调用它；先给入口写一个回归测试固定行为，再提取。
- **何时可以不改**：一次性脚本；逻辑只有几行的胶水入口。

## AP-05 循环依赖与反向依赖

- **症状**：A import B，B 又 import A（或经 C 间接）；下层模块 import 上层（`core` import `cli`）；为绕开循环把 import 挪进函数体。
- **检测**：`ARCH-CYCLE`、`ARCH-LAYER`；grep 函数体内 import：`^\s+(from \S+ )?import `（Python）；dependency-cruiser `no-circular`；import-linter `layers`/`acyclic_siblings`；clang-tidy `misc-header-include-cycle`。
- **危害**：初始化顺序问题、无法单独测试或复用、边界失去意义。
- **改法**：找出被双方共享的部分下沉为独立模块；或反转依赖（下层定义接口，上层实现并注入）；类型共享用仅类型导入（`TYPE_CHECKING`、`import type`、前置声明）。
- **何时可以不改**：同一小模块内部的两个文件互相引用且对外是一个整体（可以合并为一个文件或在配置中声明为同一层）；不能用延迟 import 作为长期方案。

## AP-06 工具模块大杂烩（utils）

- **症状**：`utils.py`/`helpers.ts`/`common.h` 持续膨胀，内容包括字符串、时间、HTTP、业务规则；几乎所有模块都 import 它。
- **检测**：文件名匹配 `(utils?|helpers?|common|misc|tools)\.(py|ts|js|h|hpp|cpp)$` 且行数 >200 或被 >50% 模块 import；内部函数之间互不相关。
- **危害**：形成隐性中心依赖，任何改动都扩散；业务规则藏在“工具”里没人找得到。
- **改法**：业务相关函数移回所属模块；通用函数按主题拆（`text.py`、`timefmt.py`）；新增函数先问“它属于哪个模块”。
- **何时可以不改**：小工具中的单个 <100 行 helpers 文件，内容确实通用且稳定。

## AP-07 跨模块读内部状态

- **症状**：模块 A import B 的 `_private` 函数或内部子模块；直接读写 B 的缓存文件、状态 JSON、数据库表；修改 B 的全局变量。
- **检测**：Python `from \S+\._\w+ import|\._\w+\(` 跨包使用；TS 跨特性目录的深路径 import（`features/[^/]+/(?!index)`）；C++ include 别的目标的 `src/` 或 `detail/`；grep 别的模块的状态文件名。
- **危害**：B 无法内部重构；状态写冲突；隐式契约无人维护。
- **改法**：B 提供公开函数或门面（[patterns P7](patterns.md#p7-门面facade)）；状态文件归 B 独占读写；用工具规则锁定（import-linter `forbidden`、boundaries 规则、CMake `PRIVATE` include）。
- **何时可以不改**：测试代码访问被测模块内部（限测试目录）；同一包内的私有协作。

## AP-08 过度抽象/投机泛化

- **症状**：只有一个实现的接口/抽象基类/工厂；“为以后扩展”的插件点、配置开关、泛型参数从未被第二个使用者用到；小工具里出现 DI 容器、事件总线、多层目录 `domain/application/infrastructure/interfaces` 但每层只有一个文件。
- **检测**：`Protocol|ABC|interface |virtual .* = 0` 的实现数 = 1；配置项从未在任何环境中被改成非默认值；调用链中有只转发参数的层；目录深度 >4 而文件数 <10。
- **危害**：阅读和修改成本上升，Agent 在多层间迷路，真实需求来临时抽象形状往往不对。
- **改法**：内联只有一个实现的抽象；删除无使用者的开关；合并空层。改动前确认没有外部调用者依赖这些接口。
- **何时可以不改**：抽象已是公开 API 且有外部使用者；已确认的近期需求（写进计划）；测试替换确实需要（P2 的单端口）。

## AP-09 一次性脚本混入正式模块

- **症状**：`fix_data_0315.py`、`test2.ts`、`try_*.cpp` 散落在根目录或 `src/`；正式代码 import 了实验脚本；脚本中的路径被复制进正式模块。
- **检测**：`ARCH-ROOT-SCRIPT`、`ARCH-LAYOUT`；文件名含日期、`tmp|temp|try|test\d|old|backup|copy`；正式模块 import 了 scratch 目录。
- **危害**：入口清单失真，后续 Agent 把实验代码当正式实现复用。
- **改法**：移到 `[layout] scratch_dirs`（项目约定的 temp/scratch 位置）；有长期价值的部分提炼进正式模块并删除副本；根目录只留项目约定的入口。
- **何时可以不改**：项目明确约定根目录入口脚本（写在 ARCHITECTURE.md 入口清单并加入 `allowed_top_level` 或豁免）。

## AP-10 生成物手改 / 生成物入源

- **症状**：手改 `*_pb2.py`、`*.generated.ts`、`dist/`、构建输出、分发生成的宿主文件；改动下次生成即丢失。
- **检测**：diff 中出现文件头含 `generated|do not edit|自动生成|@generated` 的文件；`dist/|build/|out/|__pycache__|\.egg-info|compile_commands\.json` 进入版本库。
- **危害**：源与产物分叉，问题反复出现，审查时看不出真实来源。
- **改法**：改生成器的输入或模板，重新生成；在 ARCHITECTURE.md 记录“来源 → 命令 → 输出”；把产物目录加入忽略与 `[ignore] globs`。
- **何时可以不改**：项目明确把生成结果入库（如锁文件、提交的 SDK），但仍不手改，改动只来自生成命令。
