# 版本与Git同步

## 版本规则

- 项目使用SemVer，根`package.json`的`version`为唯一机器事实源；`package-lock.json`根版本必须一致。首次可追溯功能预览为`0.1.0`，此前`0.0.1`仅为初始化占位。
- `0.x.y`表示预览阶段。兼容性修复和小幅UI调整升PATCH，例如`0.1.1`；新增能力或0.x阶段的不兼容改动升MINOR，例如`0.2.0`。稳定工作流达到发布条件后再进入`1.0.0`。
- Git版本标签为`v<version>`，使用附注标签，指向通过验证的提交；标签创建后不重写、不强推。每次版本更新同步根[CHANGELOG](../../CHANGELOG.md)。普通开发提交不必每次升版。
- 页面版本从根package.json读取，不维护另一份手写前端版本。DSH依赖版本、内部插件版本、Skill能力阶段和run编号属于不同维度，不能冒充项目版本。
- 内部插件独立采用SemVer：改变接口或新增能力时单独更新插件manifest；仅修改外层工作台布局不要求所有插件一起升版。项目标签固定当次全部组件状态。

## 同步流程

1. 查看当前分支/远端/未提交内容并fetch；确认差异归属，保留并发工作，不盲目覆盖或强推。
2. 更新版本、锁文件、CHANGELOG及必要使用说明；运行`python scripts/check_project.py`、变更范围测试。版本基线同步时执行现有离线Python/Node回归和工作台DOM冒烟；不为打标签额外消费模型或运行Zemax。
3. 审查暂存区文件与体积、凭据线索及商业模型排除规则。`.runtime/`、`runs/`、`artifacts/`、本机配置、ZMX/ZOS/ZRD/CAD不进Git。对命中线索只报告文件与原因，不能打印秘密值。
4. 提交，创建对应附注标签；在用户已授权Git同步的范围内推送当前分支及该标签。推荐原子推送，避免分支/标签只成功一半。
5. 比对远端分支提交和标签解引用提交与本地HEAD，报告提交短SHA、版本和同步结果。GitHub Release、npm发布及安装包分发是独立动作，不由普通Git同步自动触发。
