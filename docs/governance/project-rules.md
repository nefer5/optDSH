# 项目铁律手册

适用于 optDSH 项目，规则入口为根 AGENTS.md。本文件解释不可破坏的边界及验证方式；具体实现可以演进。用户后续明确指示优先于过时项目约定。

| 编号 | 铁律 | 验证方式 |
|---|---|---|
| OPT-01 | 产品面向非顶尖模型，不绑定厂商，不通过隐藏强模型兜底掩盖失败 | 每次基线记录模型/版本/日期/配置，模型切换显式可查 |
| OPT-02 | Zemax 与回读结果是光学事实源，草图和近似展示必须标注 | 对照宿主模型；图形记录来源、保真度和 revision |
| OPT-03 | 对象编号不等于永久身份，操作必须绑定模型与版本 | 插入/删除、重开、外部编辑与过期选择案例 |
| OPT-04 | 坐标框架、单位与旋转约定显式定义 | 用已知变换样例核对局部/全局姿态，不凭截图写入 |
| OPT-05 | 同一模型单一写入口，先确认意图再执行，执行后回读 | 版本冲突、重复命令、部分失败和恢复验证 |
| OPT-06 | 人的选择与标注是草稿，提交才送入 Agent；反馈绑定当时状态 | 选择不自动发请求，提交内容携带对象与 revision |
| OPT-07 | 交付、场景和运行监控分离，维护或日志不替代用户结果 | 真实界面核验；任务与仿真状态分别呈现 |
| OPT-08 | 架构声明、模拟、配置与实测不得混写 | 每个里程碑给出证据与未验证项；图片能力单独验证 |
| OPT-09 | 数据出口按部署场景管理，公司资料不进入未获准服务 | 分开个人/公司配置，核查模型、视觉、遥测和工具出口 |
| OPT-10 | 光学服务独立于 Agent 产品，领域事实不藏在提示词里 | 能独立测试光学数据/命令；适配器仅转换协议和事件 |
| OPT-14 | 需要配置文件的Skill优先采用YAML，Skill包内必须附带YAML样例 | 核对包内样例、SKILL.md入口、解析校验及run配置快照 |

## 对非顶尖模型的工程含义

优先结构化小工具、确定性计算、短闭环、结果校验和专家介入。重复失败可定位且能够停止。模型能力是被测变量，不能为通过测试悄悄改用顶尖模型；可按明确任务做对照实验并标注结果。

“非顶尖”不是永久榜单。首个具体模型暂未选定，验证时记录选择理由。开发本项目的 Codex 与产品中运行的模型是两个角色，不把该原则误用于禁止开发工具。

## 规则维护

### OPT-13 运行证据随包

所有正式分析Skill共用[运行包规范](run-bundles.md)：短ID、一次分配、默认离线HTML、执行前配置冻结、失败证据、文件校验和历史来源。验证配置修改后旧包不变、并发分配不覆盖、报告脱离项目配置仍可打开；不能只改文案而让执行器继续写散落文件。

共性边界放本文件，AGENTS.md 保持短入口，任务流程放项目 skills。新 corner case 先保存案例与证据，再决定是否值得成为长期规则。避免每次失败都追加通用铁律。

## OPT-14 Skill配置范式

- 需要配套配置文件的Skill，面向用户编辑的配置优先使用YAML（`.yaml`）；新建或改造此类Skill时遵循此约定。
- Skill包内必须在`config/`目录附带可复制的YAML样例，命名为`xxx.example.yaml`；不能只在仓库外部或根目录examples中提供。`SKILL.md`链接到包内样例，说明复制位置、加载命令、必填项、单位和必要约束。
- 样例使用合成值或明确的待填占位符，不带凭据、商业数据或未经确认的真实模型绑定。解析器应校验必填项、类型与取值范围；占位符不能误通过真实执行预检。
- 如上游接口限定JSON等格式，可以保留必要适配，但须说明原因；不能只提供一个执行器无法加载的YAML样例来宣称满足规范。
- 每次run保留当次原始YAML及实际生效配置快照，后续配置修改不影响旧run。机器使用的规范化快照、manifest和结果可继续采用JSON；输入YAML须保留原格式及扩展名。
- 既有JSON入口在迁移时验证等价解析和兼容性，不改写历史run来伪装其使用过YAML。验收覆盖样例解析、非法配置拒绝及配置随run保存；仅写入规范不代表现有执行器已支持YAML。

## OPT-12 性能持续约束

当前使用基线为每分钟一次镜片参数修改。几何计算、宿主采集、主线程渲染分别测量；不把离线加速测试写成长期实机证明。
布尔运算使用Worker与有界依赖缓存，释放WASM/GPU资源；相机/颜色操作不得重新计算布尔，四视图共享几何。
具体协议、预算及证据见 [布尔裁切与性能](../architecture/boolean-cuts.md)。
