# 架构草案

状态：设计，尚未实现。初始方案于 2026-09-25 确认。

## 分层

| 层 | 职责 | 不承担的职责 |
|---|---|---|
| OpticStudio | 权威模型、分析与光线追迹 | Agent 会话管理 |
| 独立光学服务 | API 连接、对象映射、坐标规范化、命令队列、状态快照、仿真作业 | 模型推理与界面渲染 |
| DSH 适配插件 | 工具注册、事件关联、专家反馈送入会话 | 在插件内复制光学核心逻辑 |
| Web 工作台 | 对话区、场景/画板区、独立运行区 | 凭前端几何直接生成光学结论 |

第一阶段复用官方 Web shell 和 Standard 能力组合。模型适配通过配置替换，以非顶尖模型建立基线，不依赖隐式强模型兜底。光学服务可沿用 Python/C#，在环境验证后选定；Web 渲染库在实际场景样例验证后选定。工具协议优先评估 MCP，必要时原生 DSH 插件适配。不在当前阶段引入第二套通用 Agent 调度器。

## 一次只读交互

1. 光学服务在安全读取点生成快照，绑定 modelId、revision、capturedAt。
2. Web 渲染场景，明确显示来源和当前/过期状态。
3. 用户选择对象、添加意图，显式点击提交；草稿不进入模型上下文。
4. 适配器将结构化引用与用户文字送入指定 Agent 会话。
5. 工具验证模型/对象/revision，查询真实参数；过期引用要求刷新，不能静默改指另一个对象。
6. 回答区呈现结论，运行区呈现调用、状态和结果引用。

## 一致性与写入

- Zemax 是模型事实源。网页保存展示状态，Agent 会话保存交互证据；三者不能各自拥有一份独立可写光学真相。
- 每个模型由一个服务入口串行调度写操作；读取也要遵循宿主 API 的线程与忙碌约束。
- 模型变化后发布新 revision。每次读取/修改记录版本，图表与分析结果保留生成时的版本。
- 对象稳定标识由桥接层维护；映射失效或身份不明确时拒绝操作。必须验证重新打开及外部编辑后的映射恢复，不宣称 UUID 自动解决身份问题。
- 修改生命周期：建议 → 专家确认 → 版本检查 → 保存恢复点 → 执行 → 回读 → 校验 → 发布新快照。修改失败仍需重新读取宿主状态；API 调用并不天然原子化。
- 回放日志不重新执行写命令。重复提交使用 commandId 去重，恢复策略在可写阶段前验证。

## 运行监控

Agent 事件与仿真事件关联但独立。最低关联字段：sessionId、callId（若有）、jobId、modelId、revision、时间、状态、产物引用。无法取得的上游标识明确为空，不伪造。

界面分开呈现：工具等待、模型请求、仿真运行、等待专家、错误及取消中。框架取消不等于外部作业取消；只有服务确认后才能显示已取消。

初期不承诺持续实时采集。先做操作完成后的快照刷新，忙碌时显示最后确认版本与时间，再评估增量更新成本。

## 图形与模型输入

- 第一阶段：对象树、简化几何、局部坐标轴、选择高亮。
- 后续：经验证的精确几何、代表性光线、探测器结果与前后对比。
- 草图、简化几何、抽样与真实分析必须标记来源和保真度。
- 模型默认读取结构化选择和工具结果；图片输入通过所选端点验证后再开启，不做未声明的视觉模型转发。公司资料仅走获准通道。
- 大数组留在本地二进制产物，模型只获取摘要、索引和按需切片。

## 专家介入和停转

先单 Agent、小步假设检验。相同状态下重复失败或目标长期无改善时暂停并展示已尝试内容，阈值通过案例校准。专家反馈绑定当时状态；案例保存条件、证据、纠正与验证结果，不将一次经验升级成普遍定律。
