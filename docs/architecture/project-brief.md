# 背景、目标与范围

## 用户背景（2026-09-25 会话确认）

- 用户在个人使用中体验过 Codex 的交互与工具能力；公司当前主要使用 OpenCode/Claude Code，接入 GLM-5.3，实际任务表现仍不足。
- 公司允许使用其他开源框架；限制的是模型与数据出口必须走公司 GLM 通道，而非只允许两种 Agent 产品。
- 工作频繁涉及商业仿真软件、光线建模、镜头设计及非序列布局，多模态和空间关系占比高。
- 许多问题需要专家现场评估，通用模型可能缺少领域案例，并在 corner case 中重复尝试。
- 现有工具执行过程不够透明；日志与对话交付混杂，难以同时观察模型状态和工作进度。
- 纯文字难以表达意图；已有自制 AgentCanvas，计划用绘图和标注参与协作。
- 希望在网页查看 Zemax 当前布局，点击镜片打开菜单、引用对象并向 Agent 提交约束。API 接管期间原生界面的操作/更新问题需按连接模式分别验证。

## 模型原则（用户后续明确修正）

项目不限定公司 GLM，面向可获得的非顶尖模型。希望通过结构化工具、可观察流程和专家交互提升完成质量，而不是依赖最强模型掩盖系统缺陷。具体模型和提供方可替换；“非顶尖”没有固定厂商名单或永久排名，应在每次评测中记录所选基线、日期和能力限制。

这是运行中的光学助手的设计目标，不限制开发本项目时使用 Codex 等开发工具。公司部署继续遵守其数据出口要求，个人使用合成/非敏感数据的原型不继承 GLM 唯一通道限制。

## 产品目标

1. 专家与 Agent 引用同一版本的光学模型和对象。
2. 对话交付、空间场景、运行监控能够分别查看。
3. 专家用选择、绘图、标注和确认参与任务，而非全部转换成长文字。
4. 工具提供确定性数据和计算，降低模型猜测坐标、API 和几何关系的负担。
5. 将失败与专家纠正保留为有证据、有适用条件的案例。

## 第一阶段边界

优先非序列对象的只读检查。限制到一个已知模型、一种连接模式、少量对象类型和单 Agent。网页可以先使用简化几何，前提是与真实对象身份、姿态和 revision 对齐。

不在第一阶段建设完整 Zemax 替代品、光学求解器、通用多 Agent 平台或自动训练系统。DSH 的插件化不能保证模型获得额外的物理知识或视觉能力。

## 尚待验证

- 首个模型的实际协议、工具调用、流式输出、图像输入和上下文限制；公司部署另验其网关，不保存凭据或内网地址到版本库。
- 公司工作站 OpticStudio 的版本、许可与可用连接模式。
- 目标对象的局部/全局变换语义、可提取几何范围和布局刷新时机。
- 对象身份在插入、删除、另存和重新打开后的可追踪方式。
- AgentCanvas 可复用的真实接口及提交语义，不假设已集成。
- 固定 DSH 版本中前端扩展点、模型接入及数据出口的实际表现。
