## 建议先开启到哪一步

第一阶段推荐启用Windows Sandbox本身及系统要求的依赖，先验证能正常打开一个空白沙箱。后续用最小发布产物做干净安装；无需提前把开发机所有工具装进guest。长期保留环境、旧Zemax、升级回退需要时，再配置完整持久VM。完整Hyper-V管理工具不作为第一阶段额外要求。

手动开启入口：开始菜单搜索“启用或关闭Windows功能”→勾选“Windows沙盒 / Windows Sandbox”→确定，按系统提示重启；重启后从开始菜单打开一次。也可在管理员PowerShell使用微软提供的启用命令。本轮只提供步骤，没有执行、改BIOS或重启电脑。[官方开启步骤](https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-install)

第二阶段再准备专用.wsb：发布包只读映射、结果目录可写映射，guest内独立安装，导出日志后关闭并重做一轮。具体内存按安装负载选，8–16GB可作为试验起点，属于建议值而非微软最低要求。真实模型、Zemax与许可证留到获授权的专项验收。

## 1. 为什么本地能用，换电脑却失败

开发机可能已经有 Node、Python、pnpm、个人 Agent 中心、市场插件、缓存、字体和正在运行的 Canvas/光学服务。安装包漏掉其中一项，开发机仍可能正常使用；公司电脑缺少这些隐含条件，就会失败。

验证目标是：**只拿将来真正交给用户的发布包和说明，在一台没有开发环境的 Windows 中重新安装。** 不把现役源码 checkout、node_modules、.venv、个人 home 或已经运行的服务作为隐藏前提。

## 2. 三层环境各负责什么

| 层级 | 通俗理解 | 本项目验证内容 | 不能由它证明 |
| :--- | :--- | :--- | :--- |
| Windows Sandbox | 每次可重新开始的临时干净电脑 | 前置条件、包内文件、插件组合、首次启动、synthetic与基本界面 | 任意旧版Windows、长期升级、公司网络与真实许可证 |
| 持久Windows虚拟机 | 可以保留安装并恢复检查点的测试电脑 | 安装/修复/升级/卸载、重启恢复、指定运行时、普通用户权限和旧版本适配 | 公司实际出口/域策略和设备许可证一定可用 |
| 公司实机 | 最终目标环境 | 公司插件源、代理/证书、安全策略、模型出口、目标Zemax与实际业务 | 不能用一次成功替代每个发布版本的回归 |

微软说明 Sandbox 不继承宿主已安装的软件；关闭后清除内部软件和状态，重新打开获得新实例。沙箱内部发起的重启与关闭不同，支持的系统可保留本次重启状态。导出的日志和可写映射目录内容不会随关闭被清除。[官方概述](https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/)

## 3. 将来怎样开展一轮沙箱验证

1. **准备真实发布产物**：固定版本的安装包或便携包、插件tarball、光学wheel、组件清单/哈希、前置条件与离线说明。没有正式产物时先做最小发布链，不能把源码目录当用户安装包。
2. **准备两个专用映射目录**：发布输入只读，检查结果可写。只映射测试所需内容，不映射开发机的个人配置、凭据、依赖缓存、完整研究目录或当前DSH_HOME。
3. **在沙箱内部安装**：把输入复制到内部安装区，创建独立测试home与两个合成课题目录；所需运行时在沙箱内安装，或使用发布包明确携带的运行时。
4. **先查缺依赖的报错，再测成功路径**：无Node/缺Python/插件不兼容应有明确诊断；只选择纯平台时不能强制要求光学环境。
5. **逐组合启动并交互**：包存在、登记、加载、界面交互分别检查。光学先用明确标识的synthetic，不在此阶段调用真实模型或Zemax。
6. **导出证据后关闭**：保存用例结果、版本/哈希、脱敏日志与失败截图到输出目录；再关闭并重新打开一轮，证明可以从干净状态复现。

Sandbox中的 `127.0.0.1` 是沙箱自己；不能连接宿主已经启动的3080/3081/4173后，就声称沙箱独立安装成功。也不能只在同一个已装好依赖的沙箱里重复运行，冒充冷启动安装复现。

## 4. 第一批必须覆盖的用例

这些是候选验收要求，**没有一项因写入表格而算通过**。与计划I1–I10配合使用。

| 用例 | 操作 | 通过标准 |
| :--- | :--- | :--- |
| S1 缺依赖 | 在未配置运行时的环境启动安装 | 指出缺什么、怎样补；不留下看似成功的半安装状态 |
| S2 纯平台 | 不安装工作台、Canvas、Forms、专家 | 官方会话界面可启动；没有光学/私人中心强依赖 |
| S3 工作台单装 | 工作台＋光学执行器，无Canvas/Forms | 页面/会话可用，synthetic标识正确；缺可选组件不使模块加载失败 |
| S4 画板单装 | 独立Canvas＋DSH薄桥，无光学 | 保存、显式提交、建议预览/拒绝/应用及重连回执正确 |
| S5 共同安装 | 工作台、Canvas及选定市场插件共存 | 无注册冲突，启停选择与固定版本可回读 |
| S6 两个外部课题 | 安装目录外打开A/B，包含中文与空格 | cwd、配置、画板、run归属正确；不向安装区写研究数据 |
| S7 安装中断/重复 | 断网、安装失败后修复，再运行同一安装 | 保留原始错误；重试不重复登记、不覆盖用户配置 |
| S8 离线变体 | 断网并只使用完整离线发布物 | 所选能力可安装，或明确声明该发布物不支持离线；不能临时联网补缺 |
| S9 干净复现 | 关闭沙箱，重新打开并重做所选用例 | 两轮组件清单和预期结果一致，失败记录可定位 |

普通非管理员用户、升级/卸载后数据保留、旧版Zemax和指定Windows版本放入持久VM；公司代理、模型出口和许可证仍须公司实机。沙箱默认账号或图形虚拟化不能代表普通用户权限、物理GPU性能或CUDA可用。

## 5. 不是等重构结束后才测试

第一条最小发布链可安装时，就先建立Sandbox基线；之后每次变更安装入口、依赖声明或插件组合，都重放相关用例。T10承担完整分层验收与收口，不把所有换机问题拖到最后才发现。

建议执行顺序：先S1/S2验证基础平台，再S3/S4验证独立安装，随后S5/S6验证组合与目录隔离，最后扩展中断/离线/冷启动。失败回到所属实施任务修复，保留失败证据，不以修改开发机全局环境掩盖发布缺口。
