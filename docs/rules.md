# 规则说明与作用范围

根[AGENTS.md](../AGENTS.md)是任务路由与共同协作入口。本页按作用域解释规则；编号用于追溯，不代表同表所有规则都作用于全平台。更具体的用户指示优先于过时约定。

## 平台与通用工程规则

| 编号 | 适用范围 | 要求 |
|---|---|---|
| OPT-01 | 产品架构、模型能力验收 | 可替换非顶尖模型，失败可检查，不隐藏切换强模型兜底。开发Agent的模型选择不受此条限制 |
| OPT-07 | UI与交付设计 | 用户交付、草稿/场景与运行监控分开；维护输出不替代用户答案 |
| OPT-08 | 所有能力声明 | 区分设计、模拟、配置和实测；配置成功不能冒充端到端验证 |
| OPT-09 | 数据出口与部署 | 公司资料遵守获准出口；个人合成试验与公司部署策略分开 |
| OPT-13 | 正式分析/评测/审计运行 | 一次分配短ID，实际配置、证据和结果完整随包；普通问答/文档修改不强制run |
| OPT-14 | 需要配置的Skill | YAML样例在Skill/config中，真实解析校验，实际配置随run冻结 |

近期产品验收使用glm-5.3-flash，不自动fallback；这不是对用户全部聊天或开发Codex的模型锁定。Standard会话使用官方工具、文件权限和审批，插件不因提供只读查询就禁用整个Agent的文件/Shell能力。

界面设计必须先询问是否调用视觉专家；同一任务已明确选择则沿用。公共目录、发布依赖和数据存放边界见[架构](architecture.md)，不在光学模块另建一套平台政策。

### OPT-13 运行证据随包

正式运行共用[运行包规范](runs-and-reports.md)：短ID、配置冻结、简单MD/复杂HTML、证据哈希。Study的配置和结果就近保存；历史run经用户授权可整包迁移但不改写内容。报告格式是平台共性，具体指标/对象/阈值属于领域契约、Study和Skill。

## OPT-14 Skill配置范式

- 需要配套配置文件的Skill，面向用户编辑的配置优先使用YAML（`.yaml`）；新建或改造此类Skill时遵循此约定。
- Skill包内必须在`config/`目录附带可复制的YAML样例，命名为`xxx.example.yaml`；不能只在仓库外部或根目录examples中提供。`SKILL.md`链接到包内样例，说明复制位置、加载命令、必填项、单位和必要约束。
- 样例使用合成值或明确的待填占位符，不带凭据、商业数据或未经确认的真实模型绑定。解析器应校验必填项、类型与取值范围；占位符不能误通过真实执行预检。
- 如上游接口限定JSON等格式，可以保留必要适配，但须说明原因；不能只提供一个执行器无法加载的YAML样例来宣称满足规范。
- 每次run保留当次原始YAML及实际生效配置快照，后续配置修改不影响旧run。机器使用的规范化快照、manifest和结果可继续采用JSON；输入YAML须保留原格式及扩展名。
- 既有JSON入口在迁移时验证等价解析和兼容性，不改写历史run来伪装其使用过YAML。验收覆盖样例解析、非法配置拒绝及配置随run保存；仅写入规范不代表现有执行器已支持YAML。

## OPT-12 性能持续约束

当前使用基线为每分钟一次镜片参数修改。几何计算、宿主采集、主线程渲染分别测量；不把离线加速测试写成长期实机证明。
布尔运算使用Worker与有界依赖缓存，释放WASM/GPU资源；相机/颜色操作不得重新计算布尔，四视图共享几何。
具体协议、预算及证据见 [布尔裁切与性能](contracts.md)。


## 对象呈现与入口维护

根AGENTS统一规定用户选项编号和`OBJ编号[Comment]`/`SURF编号[Comment]`引用；空备注与未记录必须区分。报告生成器使用同次证据，不凭编号查询另一版本备注。具体样式见[报告规范](runs-and-reports.md)。

写入门禁见[Zemax写入与备份](rules.md)：副本隔离、显式保存磁盘备份、未来原位修改内存恢复分别验收。能力与资料入口见[分层盘点](agents.md)，不把N02注册表、备份保留机制或Study结构写成本项目已实现功能。

## 光学模块规则：不是整个DSH的权限限制

以下仅在处理光学场景、Zemax模型或相关分析时适用。即使从Shell/Skill发起也要遵守；纯文本、普通代码或画板任务不因处在optDSH会话中就触发这些门禁。

| 编号 | 适用对象 | 要求 |
|---|---|---|
| OPT-02 | 光学数据与可视化 | Zemax/回读是事实源；近似几何与专家草图标明来源，不作真实求解依据 |
| OPT-03 | 光学对象引用 | 绑定modelId/revision，序号不是永久身份；过期引用不静默改绑 |
| OPT-04 | 光学坐标与参数 | 明确坐标、单位、参考关系和旋转含义；不能凭截图写入 |
| OPT-05 | Zemax保存或写入 | 串行入口、身份/版本检查、目标明确的授权、备份/恢复与回读 |
| OPT-06 | 光学选择/标注提交 | 选择和鼠标草稿是意图；显式提交才进入Agent，引用绑定对应版本 |
| OPT-10 | 光学服务/DSH适配 | 确定性光学能力独立于DSH；插件只适配工具、事件和界面 |

光学对象展示用OBJ编号[当前Comment] / SURF编号[当前Comment]，空与未知分开；此规则不要求普通文件/设计任务使用光学对象命名。

光学工作台的性能负载约每分钟一次参数修改，属于该模块验收基线，不限制操作频率，也不规定DSH所有界面的刷新频率。详细规则在[工作台模块AGENTS](../plugins/optdsh-workbench/AGENTS.md)；连接/执行器在[光学包AGENTS](../packages/optics/AGENTS.md)。


## 光学操作门禁：仅适用于Zemax资源

借鉴N02“写前备份、身份核验、失败即停、明确恢复范围”，按optDSH已有操作分支适配。规则本身不授予活动模型修改权限。

### 按操作分类

| 操作 | 前置条件和恢复要求 | 当前实现 |
|---|---|---|
| 只读inspect/plan/dry-run | 不调用Save、不清detector、不触发恢复写入；dirty也不能自动保存 | capture与各Skill只读入口 |
| 独立CopySystem分析 | 确认副本独立身份与模型版本后才写副本；关闭副本、回读主系统/dirty/磁盘哈希与相关字段 | Tx、Rx执行器；不调用会Save主模型的N02备份器 |
| 用户显式保存当前模型 | 校验实例、文件、系统ID、revision；dirty时先校验复制旧磁盘，再调用Save并回读；清洁模型无需重复写盘 | packages/optics/src/optdsh_optics/model_save.py，save_connected/execute_save_run |
| 活动模型原位参数修改 | 执行前设计能恢复“当前内存状态”的备份；与用户确认保存副作用、恢复范围，再走同一公共写入口；失败禁止后续setter | 尚未提供通用产品入口，不得把显式保存当成参数修改授权 |

### 已实现的保存门禁

- 用户点击标明目标的保存按钮即授权该次保存，无需重复询问；探测、刷新、绑定不授权保存。
- 保存通过服务串行调度并使用公共排他锁；不允许脚本与服务并发修改同一模型。
- 旧磁盘文件保存在当次`runs/model-save/YYMMDD-NN/backup/`，公共RunBundle负责复制与SHA-256校验，检查复制期间源文件未变；run记录原路径、哈希、dirty、是否尝试Save及回读。
- 这是**保存前的磁盘版本备份**，不是未保存内存状态备份。不得把它用于声称可恢复尚未保存的全部模型修改。
- 文件缺失、身份/版本变化、备份/校验失败均禁止Save。Save异常、超时或回读不一致标记不确定，保留证据、不自动重放或回滚。
- 不手工修改ZMX/ZDA字节。恢复由用户明确选择，在关闭/另存当前模型后进行；普通报告整理不恢复模型。

### 与N02的差异及后续门槛

N02公共备份器会在授权原位修改后先Save dirty模型，再备份当前文件。不能在optDSH的只读或副本流程中直接调用，否则改变主模型与磁盘。未来原位setter开发必须先实现并验证内存恢复策略，必要时同时保留旧磁盘版本和经明确授权保存后的当前版本。

本项目尚未采用集中`backups/zemax/`、按文件分组保留5份或自动回收机制；本次保留已验证的run备份路径，不虚称这些功能已实现。若迁移集中备份，须统一迁移引用、恢复说明和测试，不在单个Skill复制另一套备份器。

ZDA不在现有轻量磁盘备份内。依赖ZDA、外部CAD/材料/源文件或其他宿主状态才能恢复的操作，应先明确完整恢复方案并取得相应授权；不能仅凭一个ZMX哈希宣称全部可恢复。

实现验证参考packages/optics/tests/test_model_save.py；真实验证状态见[当前状态](../planning/STATUS.md)，保存入口见[工作台说明](workbench.md#保存当前模型)。
